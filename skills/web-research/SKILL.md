# Web Research 联网调研

把「查资料 → 读网页 → 整理结论」变成一套可复用流程。适合用户需要快速了解某个话题、产品或技术时的调研任务。

## 使用时机
- 用户说"帮我查一下/调研/了解/搜索 X"
- 需要多个信息源交叉验证的问答
- 需要保存调研结论供后续使用的任务

## 执行流程

### 1. 确认需求（30 秒内）
- 明确调研主题、期望产出（一段总结 / 对比表格 / 带来源的清单）
- 明确时效性要求（最新的 vs 综合性的）

### 2. 多源收集（并行进行）
- 先用搜索工具（`search` / `search_and_crawl` / `research`）搜索互联网获取相关 URL
- 再用 `fetch` 抓取高价值链接的网页正文
- 已安装的 MCP：`duckduckgo-websearch` 提供搜索工具
- 已安装的 MCP：`mcp-fetch` 提供 `fetch` 工具可抓取任意 URL 内容
- 已安装的 MCP：`playwright-mcp` 提供浏览器工具可操作需要登录或动态渲染的页面
- 优先官方文档、权威来源；技术问题优先查官方 release notes / docs

### 3. 交叉验证
- 至少 2 个独立来源确认关键事实
- 标注来源 URL，区分"事实"与"推测"

### 4. 产出
- 中文总结，术语保留英文原词并附简短解释
- 结构：结论先行 → 要点分条 → 来源列表 → 注意事项
- 若用户需要，把结果保存为工作区内的 markdown 文件

## 注意事项
- 不编造来源：每条事实都要能追溯到实际抓取到的内容
- 网页抓取失败时，换搜索引擎缓存或换 URL 重试，不要硬编
- 用户是新手：解释时用大白话，避免堆术语
